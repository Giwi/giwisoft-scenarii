How it works

Three moves. Then it runs itself.

01

Write YAML

Define steps, assertions, variables, and conditions in a plain file. No SDK, no test code.

02

Put it on cron

Scenarii schedules runs, watches the scenario folder, and keeps every result in SQLite.

03

Get the signal

Failures and recoveries go to Telegram, Slack, Discord, email, or your own webhook.

scenarios/api-health.yml 
# Run every 5 minutes
name: API health check
schedule: "*/5 * * * *"
base_url: https://api.example.com

steps:
  - name: Get health
    action: http.get
    url: /health
    expect:
      status: 200
      response_time_under: 3000

  - name: Verify build
    action: http.get
    url: /health
    expect:
      json_path: $.build
      json_value: "ok"

  - name: Create session
    action: http.post
    url: /sessions
    body:
      user: monitor
    expect:
      status_in: [200, 201]

A scenario is just YAML.

Steps, expectations, extraction variables, and conditions. The API and the browser use the same file format.

scenarios/example.yml 
# scenarios/example.yml
name: API health check
description: Verify API health every 5 minutes
schedule: "*/5 * * * *"
base_url: https://jsonplaceholder.typicode.com

steps:
  - name: Get posts
    action: http.get
    url: /posts/1
    expect:
      status: 200
      response_time_under: 3000

  - name: Verify JSON content
    action: http.get
    url: /posts/1
    expect:
      status: 200
      json_path: $.userId
      json_value: 1

  - name: Create a post
    action: http.post
    url: /posts
    body:
      title: foo
      body: bar
      userId: 1
    headers:
      Content-Type: application/json
    expect:
      status: 201
scenarios/browser-example.yml 
# scenarios/browser-example.yml
name: Browser form test
description: Test page load and content rendering
schedule: "*/10 * * * *"
base_url: https://example.com

steps:
  - name: Open page
    action: browser.navigate
    url: /

  - name: Verify page loaded
    action: browser.wait_for
    selector: body
    expect:
      has_text: "Example"

  - name: Fill the form
    action: browser.fill
    selector: "#name"
    value: "Jane Doe"

  - name: Submit
    action: browser.click
    selector: "#submit"

  - name: Wait for result
    action: browser.wait_for
    selector: ".success-message"
    timeout: 5000
    expect:
      has_text: "Thank you"

  - name: Screenshot
    action: browser.screenshot
    value: /tmp/screenshot.png
scenarios/mixed.yml 
# scenarios/mixed.yml
name: Mixed browser and HTTP
base_url: https://example.com

steps:
  - name: Open page
    action: browser.navigate
    url: /
    expect:
      has_text: "Example"

  - name: Check external API
    action: http.get
    url: https://jsonplaceholder.typicode.com/posts/1
    expect:
      status: 200

      json_value: 1
scenarios/conditional.yml 
name: Conditional scenario
base_url: https://jsonplaceholder.typicode.com

steps:
  - name: Login
    action: http.post
    url: /auth/login
    body:
      username: admin
      password: secret
    expect:
      status: 200
    variables:
      token: $.access_token    # extract from response

  - name: Dashboard check
    action: http.get
    url: /api/dashboard
    condition:               # skip if Login failed
      if_step: "Login"
      if_success: true
    headers:
      Authorization: "Bearer {{token}}"
    expect:
      status: 200
scenarios/variables.yml 
name: Variable extraction demo
variables:                    # resolved before the first step
  API_TOKEN: "{{env.API_TOKEN}}"
  API_BASE: "{{env.API_BASE:-https://jsonplaceholder.typicode.com}}"
base_url: "{{API_BASE}}"
headers:                      # shared by every HTTP step
  Authorization: "Bearer {{API_TOKEN}}"

steps:
  - name: Get first post
    action: http.get
    url: /posts/1
    expect:
      status: 200
    variables:
      postTitle: $.title       # extracted from response
      postId: $.id

  - name: Get user for post
    action: http.get
    url: /users/{{postId}}
    expect:
      status: 200

  - name: Verify content
    action: http.get
    url: /posts/{{postId}}
    expect:
      body_contains: "{{postTitle}}"

{{env.NAME}} reads the process environment and {{NAME:-fallback}} applies when a value is missing or empty. Step headers override scenario headers by name.

Local users

First start creates an admin and prints a generated password once in the logs.

  • admin manages users, roles, and passwords.
  • user browses scenarios, triggers runs, and pauses schedules.
  • HTTP-only session cookies. The last admin cannot lock itself out.

OIDC and SSO

Point Scenarii at your provider and roles follow group membership on every login.

  • username_claim falls back to preferred_username, email, then sub.
  • groups_claim accepts arrays, strings, or comma-separated lists.
  • admin_group grants admin. Everyone else gets user.
settings.yml 
auth:
  oidc:
    issuer_url: "https://accounts.google.com"
    client_id: "YOUR_CLIENT_ID"
    client_secret: "YOUR_SECRET"
    username_claim: "preferred_username"
    groups_claim: "groups"
    admin_group: "scenarii-admins"

What happens next

Open http://localhost:3000. The first start prints a generated password for the admin user in the logs.

Scenarios load from ./scenarios. Add, remove, or rename a YAML file and the server picks it up within five seconds.

Settings live in settings.yml and reload on save. Notifications are off until you configure a channel.

Images are published for linux/amd64 and linux/arm64.

Authentication

Route protection, local roles, and OIDC group mapping.

Authentication is on by default. Every page is private except the public status pages, and every API route needs a session cookie except health, status, metrics, and auth endpoints. Set auth.enabled: false to turn it off.

Roles

RoleCan do
adminEverything a user can, plus add, promote, demote, and delete users.
userBrowse scenarios, view history and charts, trigger and pause runs.

An admin can neither delete their own account nor change their own role, so the last admin cannot be locked out of user management.

OIDC notes

  • username_claim is used as the local username. Unset, it falls back to preferred_username, then email, then sub.
  • groups_claim is read as a group list. Arrays, plain strings, and space or comma separated strings are accepted. groups and roles are fallbacks.
  • admin_group membership grants the admin role. Everyone else gets user. Without it, every OIDC user is a plain user.
  • The role is re-derived on every login. Changing group membership applies on the next sign-in.
settings.yml 
auth:
  enabled: true
  default_user: admin
  default_user_role: admin
  oidc:
    issuer_url: "https://accounts.google.com"
    client_id: "YOUR_CLIENT_ID"
    client_secret: "YOUR_CLIENT_SECRET"
    redirect_uri: "http://localhost:3000/api/auth/callback"
    username_claim: "preferred_username"
    groups_claim: "groups"
    admin_group: "scenarii-admins"

Notifications

Five channels, state transitions, per-scenario overrides, retries.

Alerts fire when a scenario changes state: pass to fail, or fail to pass. Delivery retries three times with exponential backoff. The server watches settings.yml and reloads it on change.

Channels

ChannelConfiguration
TelegramTELEGRAM_BOT_TOKEN and TELEGRAM_CHAT_ID, or the settings file.
EmailSMTP (host/port, optional auth, TLS/STARTTLS, and certificate verification with a custom CA) or Mailgun API key and domain. Multiple recipients. Daily report at 08:00.
SlackWebhook URL. JSON payload with scenario, status, and duration.
DiscordWebhook URL. Embedded message with color-coded pass or fail.
Generic webhookAny endpoint that accepts the JSON payload.

Secrets can be overridden with environment variables such as TELEGRAM_BOT_TOKEN, MAILGUN_API_KEY, MAILGUN_DOMAIN, SMTP_HOST, SMTP_PORT, SMTP_USERNAME, SMTP_PASSWORD.

HTTP actions

Methods, expectations, and step options.

Every step needs a name and an action. HTTP steps use native fetch. No browser or Playwright required.

HTTP steps do not retry by default. Set retries to retry a failed request or expectation, and retry_delay (ms) to control the wait between attempts.

Actions

ActionRequiredOptional
http.geturlheaders, expect
http.posturlheaders, body, expect
http.puturlheaders, body, expect
http.patchurlheaders, body, expect
http.deleteurlheaders, expect

Expectations

ExpectationDescription
status: 200Exact HTTP status code match.
status_in: [200, 201]Status code is one of the listed values.
body_contains: "text"Response body contains the string.
body_matches: "regex"Response body matches the regex.
header_contains: "Content-Type: json"Header contains the value, in "HeaderName: value" form.
header_matches: "X-RateLimit: \\d+"Header matches the regex, in "HeaderName: regex" form.
json_path: "$.user.id"Extract a JSON path, optionally check json_value.
json_value: 42Value at json_path must match.
response_time_under: 3000Response time must be under the given milliseconds.
body_schema: { type: object, required: [id] }Validate the JSON body. Supports type, properties/required, items, enum, pattern, min/max, and nullable.

Step options

FieldTypeDescription
timeoutnumberPer-step timeout. Default 30s for browser, 10s for HTTP.
conditionobject{ if_step: "Step name", if_success: true } skips unless the named step matched.
variablesobjectExtract from JSON responses: { varName: "$.json.path" }. Use {{varName}} later. Missing variables fail the step before the request is sent.
expectobjectAssertions on status, body, headers, JSON, and response time.

Browser actions

Lightpanda via Playwright CDP, with retries.

Browser steps run through a headless Lightpanda instance. Failed steps retry twice, waiting retry_delay ms (default 1000) between attempts. Override per step with retries and retry_delay. browser.evaluate, browser.screenshot, and browser.screenshot_compare never retry.

ActionFieldsDescription
browser.navigateurlNavigate. Falls back to domcontentloaded if load does not fire.
browser.clickselectorClick with actionability checks: visible, enabled, stable, in viewport.
browser.fillselector, valueFill using native setters, reliable with React and Angular controls.
browser.typeselector, valueType and dispatch input plus change.
browser.selectselector, valueSelect an option from a <select>.
browser.checkselectorCheck a checkbox or radio button.
browser.uncheckselectorUncheck a checkbox.
browser.wait_forselector, timeout, expectWait for an element. Check has_text, not_has_text, or url_contains.
browser.evaluatescriptRun JavaScript in the page context.
browser.scrollvalue or selectorScroll by pixels, or scroll an element into view.
browser.screenshotvalue (path)Full-page screenshot to the given path.
browser.screenshot_comparevalue (baseline path)Compare against a baseline. Creates it on first run, reports diff percentage after.

CLI and server options

Validate, trigger, inspect, and configure.
terminal 
# Start API server and dashboard
node dist/index.js server -p 3000 --db db/scenarii.db --scenarios-dir ./scenarios

# Validate without running (checks schema, unknown fields, cron, required fields)
node dist/index.js validate scenarios/example.yml
node dist/index.js validate --all --json

# Run immediately (exits 1 on failure; add --fail-on none to always exit 0)
node dist/index.js trigger scenarios/example.yml

# Scheduled scenarios and storage status
node dist/index.js status

# Generate a settings template
node dist/index.js config --init

trigger <file>Run immediately, with no scheduling.
statusList scheduled scenarios and show database connectivity.
user <action>list, add, passwd, role, del.
config --initGenerate settings.yaml with channels commented out.
