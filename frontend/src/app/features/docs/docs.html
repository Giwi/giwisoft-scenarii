Creating scenarios

A scenario is one YAML file dropped in the scenarios directory. The directory is rescanned every 5 seconds, so a new file starts running without a restart. Validate a file before relying on it with node dist/index.js validate <file>.

The file

Only name and steps are required. Everything else is optional: a scenario without a schedule runs on demand only. 

name: API health check
description: Verify the API answers every 5 minutes
schedule: "*/5 * * * *"
base_url: https://jsonplaceholder.typicode.com

steps:
  - name: Get post 1
    action: http.get
    url: /posts/1
    expect:
      status: 200
      json_path: $.id
      json_value: 1
      response_time_under: 2000

Steps

Steps run in order, each one recording its own duration, status, and pass/fail result in the run history. The first failed expectation fails the step; the run fails unless you carry on.

HTTP actions

Plain HTTP through native fetch, no browser involved. HTTP steps never need the headless browser, so they stay fast.

{{ a.action }} 
- name: Create a post
  action: http.post
  url: /posts
  headers:
    Content-Type: application/json
  body:
    title: foo
    body: bar
    userId: 1
  expect:
    status: 201

Browser actions

A headless browser is started automatically as soon as a scenario contains at least one browser step. Steps share one page, so a navigation followed by a click behaves like a session.

{{ a.action }} 
- name: Open the page
  action: browser.navigate
  url: /

- name: Wait for the list
  action: browser.wait_for
  selector: app-news-article
  timeout: 5000

- name: Filter by region
  action: browser.evaluate
  script: |
    const select = document.querySelector('select');
    select.value = 'Bretagne';
    select.dispatchEvent(new Event('change'));

- name: Search
  action: browser.fill
  selector: "#query"
  value: "Brest"

Several expectations can sit in the same expect block: all of them are checked, and the step passes only when all pass.

Variables

A step extracts values from its response with variables, and later steps reuse them with {{ mustaches }}. The key is the name you choose, the value is the JSON path to read. 

- name: Get the post
  action: http.get
  url: /posts/1
  variables:
    postId: $.id

- name: Get that post again
  action: http.get
  url: /posts/{{ mustaches }}
  expect:
    status: 200

Variables are interpolated into urls, headers, body values, selector values, and expected text.

Sharing steps

An include step inlines the steps of another scenario file, matched on its name or its filename. An optional name prefixes every included step name, which keeps the history readable when the same block is reused twice. 

steps:
  - include: login
  - include: checkout
    name: checkout

  - name: Place the order
    action: browser.click
    selector: "#submit"

Circular includes are rejected when the file is parsed.

Conditions

A condition skips a step unless a previous step behaved as expected, which lets a scenario branch instead of failing. 

steps:
  - name: Open the page
    action: browser.navigate
    url: /

  - name: Accept the cookie banner
    action: browser.click
    selector: "#cookie-accept"
    condition:
      if_step: Open the page
      if_success: true

The skipped step records no result, so a condition never turns a passing scenario into a failing one.
